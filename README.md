# tree-sitter-mapfile

> [!NOTE]
> This project is AI-written. Claude (Opus 5.5) wrote the grammar, queries,
> tests and docs in Claude Code, and I tested the result in Helix. It's a
> personal project with no guarantees. Issues and PRs are welcome.

A [tree-sitter](https://tree-sitter.github.io/) grammar for MapServer
[Mapfiles](https://mapserver.org/mapfile/), mainly for syntax highlighting in
[Helix](https://helix-editor.com/). It is ported from the Lark grammar in
[mappyfile](https://github.com/geographika/mappyfile) (`mappyfile/mapfile.lark`)
and keeps its rule names.

It handles full `MAP` files, `SYMBOLSET` files, `CONFIG` files and partial
mapfiles (a lone `LAYER`, several `CLASS` blocks, included fragments). It parses
462 of the 464 sample `.map` files in mappyfile's test suite without errors. The
other two are broken on purpose.

Because the goal is highlighting, the grammar is more permissive than
mappyfile's: it doesn't check which keys belong in which block. For validating a mapfile, use
mappyfile itself.

## Helix

The `queries/` directory has `highlights.scm`, `indents.scm`,
`textobjects.scm` and `folds.scm`, using Helix's capture names.

### Nix (flake)

The flake exports what a Nix-managed Helix config needs:

- `packages.<system>.default`: the built grammar (`parser` and `queries/`).
- `packages.<system>.helix-runtime`: `grammars/mapfile.so` and
  `queries/mapfile/`, laid out like a Helix runtime dir.
- `lib.helixLanguage`: the `[[language]]` entry as a Nix attrset.

```nix
inputs.tree-sitter-mapfile = {
  url = "github:lnus/tree-sitter-mapfile/v0.1.1";
  inputs.nixpkgs.follows = "nixpkgs";
};
```

Link `helix-runtime`'s `grammars/mapfile.so` and `queries/mapfile` into
`<helix config dir>/runtime/`, and add `lib.helixLanguage` to the `language`
list of your `languages.toml`.

### Nix (development)

The flake's dev shell has `tree-sitter` and an `hx-dev` command. `hx-dev`
sets up a Helix config dir in `~/.cache/tree-sitter-mapfile/`: it compiles the
grammar there, links `queries/` in, and adds a `languages.toml` generated by the
flake. Then it starts Helix with that config dir. You don't need
`hx --grammar build`, which can't write to a read-only Nix store runtime.

```sh
nix develop          # or: direnv allow
hx-dev examples/centerline.map
hx-dev --health mapfile
```

`hx-dev` rebuilds the grammar when `src/parser.c` changes. Query edits apply
when you reopen a file. Helix runs with its default settings, not your own
config. The language settings are `lib.helixLanguage` in `flake.nix`.

### Regular install

Add this to `~/.config/helix/languages.toml`:

```toml
[[language]]
name = "mapfile"
scope = "source.mapfile"
file-types = ["map", "sym"]
comment-token = "#"
block-comment-tokens = { start = "/*", end = "*/" }
indent = { tab-width = 4, unit = "    " }
grammar = "mapfile"

[[grammar]]
name = "mapfile"
# v0.1.1
source = { git = "https://github.com/lnus/tree-sitter-mapfile", rev = "0fb0416164a5e4ee72b61db3c2ac0f3b8d131948" }
```

Then fetch and build the grammar, and link the queries from the fetched source
so they stay in sync with the pinned revision:

```sh
hx --grammar fetch
hx --grammar build
mkdir -p ~/.config/helix/runtime/queries
ln -s ~/.config/helix/runtime/grammars/sources/mapfile/queries ~/.config/helix/runtime/queries/mapfile
hx --health mapfile
```

To update, change `rev` to the commit of a newer
[release tag](https://github.com/lnus/tree-sitter-mapfile/tags) and run the
fetch and build commands again.

## Development

```sh
tree-sitter generate                                # after every grammar.js change
tree-sitter test                                    # corpus tests in test/corpus/
tree-sitter parse examples/*.{map,sym,cfg} --quiet --stat
tree-sitter parse file.map                          # print the tree for one file
```

`CLAUDE.md` has the porting notes (Lark → tree-sitter) and the conventions.
