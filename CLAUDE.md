# tree-sitter-mapfile

A tree-sitter grammar for MapServer Mapfiles. It is ported from the Lark grammar
in [mappyfile](https://github.com/geographika/mappyfile) (`mappyfile/mapfile.lark`).

The project is AI-assisted (mostly written by Claude, with manual changes on
top), and the README says so. Keep that note accurate if the README changes.

## Goal

Syntax highlighting (plus folding, indents and textobjects) in Helix, and in
Neovim through a second query set in `queries/neovim/`.

The grammar can be **looser than Lark's**. Tree-sitter's error
recovery covers edge cases, so don't encode validation rules (which keys are
allowed in which block, and so on). mappyfile does that with JSON schemas.

## Status

The grammar, the four queries and the corpus tests work, and the queries have
been checked in Helix with `hx-dev`. Baseline for the mappyfile corpus: 462 of
464 `.map` files parse without errors. The two failures are broken on purpose:
`quoted_text.MAP` is binary junk, and `style-size.map` is missing an `END`.
Both are on mappyfile's own ignore list. A change that lowers that number is a
regression.

## Source of truth

- `mapfile.lark` in mappyfile is the reference for syntax. When the two
  disagree, check what MapServer actually accepts before copying Lark's
  behaviour. Some of it is a workaround for LALR(1).
- mappyfile's test suite has real-world `.map` files. Use them as the parse
  corpus. mappyfile isn't vendored, so clone it outside the repo (for example
  into a scratch directory). `examples/` only has a few copied files.

## Layout

```
grammar.js               # the grammar
src/                     # generated by `tree-sitter generate`; commit it (Helix builds from src/parser.c)
queries/highlights.scm   # Helix capture names (see below)
queries/folds.scm        # BLOCK ... END (Helix doesn't fold yet; for other editors)
queries/indents.scm
queries/textobjects.scm  # blocks = @class, func calls = @function
queries/neovim/*.scm     # same four for Neovim (nvim capture names; see below)
test/corpus/*.txt        # tree-sitter test cases
examples/                # sample files from mappyfile and MapServer (see its README)
THIRD-PARTY-NOTICES.md   # licenses for the mappyfile port and the copied examples
flake.nix                # grammar package, helix-runtime, lib.helixLanguage; dev shell with hx-dev
```

## Commands

```sh
tree-sitter generate           # after every grammar.js change
tree-sitter test               # corpus tests
tree-sitter parse examples/*.{map,sym,cfg} --quiet --stat   # count files that fail to parse
tree-sitter parse file.map     # print the tree for one file
tree-sitter parse --paths <list-of-mappyfile-maps> --quiet --stat   # full corpus
tree-sitter query queries/highlights.scm file.map   # which capture each node gets
hx-dev file.map                # Helix with this grammar (see below)
```

To fill in a new corpus test, write the input with an empty tree, run
`tree-sitter test --update`, then **read the generated tree**. `--update`
records whatever the grammar produces, including wrong trees.

## Porting notes (Lark → tree-sitter)

Maps directly:
- Rules → `seq` / `choice` / `repeat` / `optional`.
- Expression layers (`or_test`, `and_test`, `comparison`, `sum`, `product`,
  `unary_expr`) → `prec.left(n, ...)` with explicit precedence levels (`PREC`
  in grammar.js). `NOT` sits between `and` and `comparison`.
- `%ignore COMMENT/CCOMMENT/WS/_NL` → `extras`. Both comment styles become one
  `comment` node.
- Lark's contextual lexer ≈ tree-sitter's context-aware lexer, so collisions
  like regex vs. `/` vs. path mostly behave the same.

Needs care:
- **No lazy quantifiers or lookahead in tree-sitter regexes.** Rewrite
  `REGEXP1`, `REGEXP2`, `RUNTIME_VAR`, `ESCAPED_STRING` (`.*?`) and `CCOMMENT`
  (use the standard C block-comment regex). `INT` uses `(?![_a-zA-Z])`; here
  plain longest-match does the same job (see token precedence below).
- **Case-insensitive keywords.** tree-sitter 0.26 supports regex flags, so
  `kw("CLASS")` in grammar.js is `alias(/CLASS/i, "CLASS")`, which gives an
  anonymous `"CLASS"` node to query. `word: $ => $.unquoted_string` makes
  keyword extraction work, and a keyword that isn't valid in the current
  state falls back to `unquoted_string` (`NAME class`, keys inside CONFIG).
- **STYLE / SYMBOL are both block openers and attribute keys**, and inside
  `CONFIG` any block keyword can be a key. No `conflicts` are needed: the
  token after STYLE/SYMBOL decides (a value → attribute, a key or `END` →
  block; for SYMBOL only its own keys like `NAME`/`TYPE` open a block).
  `STYLE` followed by `NORMAL|HILITE|SELECTED` in QUERYMAP is an attribute.
- **Token precedence beats match length in tree-sitter.** `token(prec(n, ...))`
  on `int` would lex `5abc` as `5` + `abc`, and on `regexp` it would lex
  `/data/x.shp` as `/data/` + junk. So `int`, `float`, `regexp`, `path` and
  `unquoted_string` have no prec: the longest match wins, and ties go to the
  rule defined first. Only `hexcolor` (vs. `string`) and `comment` use prec,
  where the winner is never shorter.
- **`alias(seq(...), $.x)` doesn't wrap the sequence in an `x` node.** To rename
  a multi-token rule, make it a named rule and alias it where it's used (see
  `symbol_attr`, which shows up as `attr`). A rule that is only ever aliased
  doesn't exist in the tree, so queries can't name it.
- **INCLUDE** is expanded as text in mappyfile. Here it's just an `include`
  node. Never try to resolve files.
- Top level can be a `MAP`, a bare `SYMBOLSET`, a `CONFIG` file, or a list of
  composites (partial mapfiles such as a lone `LAYER` or several `CLASS`
  blocks). All four must parse. `source_file` accepts any composite item,
  including bare attributes, which covers included fragments.

Deliberate differences from Lark:
- No `composite_body` wrapper, because tree-sitter rules can't match the empty
  string. Items sit directly under `composite`, `symbolset`, and so on.
- The top-level CONFIG file is `config_file` (with `env`, `maps`, `plugins`).
  `config` is the `CONFIG "key" "value"` item inside a MAP. Lark names both
  `config`.
- `composite_type` is a leaf node, including for STYLE/SYMBOL blocks.
- Number groups (`num_pair`, `rgb`, `extent`, `colorrange`) are told apart
  only by count, and all of them accept ints and floats.
- Expression atoms are a subset of Lark's `value` (no pairs or colours), which
  avoids conflicts.

## Helix integration

On NixOS, `hx --grammar build` can't write to the store runtime. Use
`hx-dev` from the dev shell instead (defined in `flake.nix`):

- Its config dir is `~/.cache/tree-sitter-mapfile/xdg/helix/`, outside the
  repo. It compiles `mapfile.so` into `runtime/grammars/` there when
  `src/parser.c` is newer, and symlinks `queries/` in as
  `runtime/queries/mapfile`.
- The language entry (file types, comments, indent) is `lib.helixLanguage` in
  `flake.nix`. `hx-dev` turns it into a `languages.toml` with `pkgs.formats.toml`,
  and Nix consumers (the user's `~/nix` Helix wrapper) import it directly, so
  change it there only. There's no `config.toml`, so Helix
  runs with default settings. (The user configures Helix through a Nix wrapper
  module, not `~/.config/helix`.)
- It runs nixpkgs' Helix with `XDG_CONFIG_HOME` pointing there. Helix searches
  `<config dir>/runtime` before `$HELIX_RUNTIME`, so the other languages still
  work.
- Check it with `hx-dev --health mapfile`. The parser and all three query
  kinds should show ✓.

`hx-dev` builds from the working tree. The flake's `packages` (`default` =
`buildGrammar` output, `helix-runtime` = a Helix-shaped runtime dir) build from
`src/`, `queries/` and `tree-sitter.json` only, and take the version from
`tree-sitter.json`. `nix build .#helix-runtime` is the quick check for them.

The regular (non-Nix) install is in the README.

Use Helix's capture names in `highlights.scm` (not nvim-treesitter's). In
Helix **the first matching pattern wins**, so put specific patterns before
generic ones. Current mapping:
`keyword` (block names, `END`), `variable.other.member` (attribute keys),
`string` (strings, hex colours), `string.regexp`, `string.special.path`,
`constant.numeric.integer` / `.float`, `constant.builtin.boolean`,
`constant` (`AUTO`, `NULL`, style modes, unquoted values), `function`
(function calls in expressions), `operator`, `punctuation.bracket`,
`punctuation.delimiter`, `comment`, `variable` (`[attr]` bindings,
`%runtime%` vars).

## Neovim integration

`queries/neovim/` mirrors the four Helix queries with Neovim's capture names.
Keep the two sets in sync when a query changes. nvim-treesitter (main branch)
installs them through `install_info.queries = 'queries/neovim'` (see the
README). Differences:

- In Neovim **the last matching pattern wins**, so `highlights.scm` is in
  reverse order: generic patterns first, keys and specific patterns last.
- Highlight names: `property` (keys), `number` / `number.float`, `boolean`,
  `constant.builtin` (`NULL`, `AUTO`), `keyword.operator` (`AND`/`OR`/`NOT`),
  `keyword.import` (`INCLUDE`), `function.call`, `comment @spell`.
- Indents: `@indent.begin` on blocks, `"END" @indent.branch @indent.end`.
  These need nvim-treesitter's `indentexpr`.
- Textobjects: `.outer`/`.inner` instead of `.around`/`.inside`, and function
  calls are `@call` (nvim-treesitter-textobjects' name).
- Neovim's built-in filetype for `.map` is `map`; the README registers
  `mapfile` for it and maps `.sym` to it too.

To test without touching the user's config, run Neovim from nixpkgs
(`nix shell nixpkgs#neovim`) with `XDG_*_HOME` pointed at a scratch dir and a
minimal `init.lua` that clones nvim-treesitter's `main` branch and uses
`install_info.path` for the local checkout. A flattened file reindented with
`gg=G` should match the original.

## Conventions

- Keep node names close to the Lark rule names (`composite`, `attr`,
  `string_pair`, `num_pair`, `expression`, ...) so the two grammars can be
  compared side by side.
- Every grammar fix gets a corpus test.
- Releases are annotated `vX.Y.Z` tags, matching `metadata.version` in
  `tree-sitter.json`. The README's Helix install pins `rev` to the tagged
  commit's full hash (Helix wants a commit hash), so update it after tagging.
- Commit messages follow [Conventional Commits](https://www.conventionalcommits.org/):
  `<type>(<optional scope>): <subject>`, e.g. `feat(nix): export helix runtime`,
  `fix(grammar): allow floats in extent`, `docs: ...`. Types: `feat`, `fix`,
  `docs`, `test`, `refactor`, `chore`, `build`. Older commits predate this.
- After a grammar change, run `tree-sitter test` and the full mappyfile corpus,
  and check that `hx-dev --health mapfile` still loads the queries. A query
  that names a node which no longer exists fails to load. The same goes for
  `queries/neovim/`: `tree-sitter query queries/neovim/highlights.scm file.map`
  fails on a bad node name.
